# Release Process

## Versioning

Single source of truth = version string in three files, kept in sync:

- `src-tauri/Cargo.toml` → `[workspace.package].version`
- `src-tauri/tauri.conf.json` → `version`
- `package.json` → `version`

Follow semver: `0.MINOR.PATCH` until v1.0 (currently pre-1.0, minor bumps can include breaking changes).

## Steps to cut a release

```bash
# 1. Bump all three version files to e.g. 0.1.13
# 2. Refresh Cargo.lock
cargo update -p my-media-kit --manifest-path src-tauri/Cargo.toml

# 3. Commit + tag + push
git add -u
git commit -m "feat: v0.1.13 — <summary>"
git tag v0.1.13
git push origin main
git push origin v0.1.13
```

The tag push triggers [`.github/workflows/release.yml`](../.github/workflows/release.yml).

## What CI does

1. **`build-macos`** (runs-on: macos-14, Apple Silicon)
   - Downloads `ffmpeg`/`ffprobe`/`yt-dlp` for aarch64-apple-darwin into `src-tauri/binaries/`
   - Imports signing cert + entitlements
   - Runs `npm run build` → produces `.dmg` + `.app.tar.gz` (+ `.sig` for updater)
   - Notarises via Apple API (credentials in repo secrets — see list below)
   - Uploads artifacts

2. **`build-windows`** (runs-on: windows-latest)
   - Downloads Windows binaries for `x86_64-pc-windows-msvc`
   - Builds `.msi` + `.exe` + `.sig`
   - Uploads artifacts

3. **`release`** (runs-on: ubuntu-latest)
   - Downloads both platform artifacts
   - Generates `latest.json` for the tauri-plugin-updater
   - Creates GitHub Release as **draft**
   - Attaches all assets

## After CI finishes

CI leaves the release as **Draft**. To publish:

```bash
gh release edit vX.Y.Z --draft=false --latest --notes "..."
```

Or edit in GitHub UI. The app's auto-updater polls the `latest` release, so:

- Only one release at a time should be `Latest: true`
- The `latest.json` endpoint must resolve to the version you're shipping

## Secrets required in CI

| Secret | Purpose |
|---|---|
| `APPLE_CERTIFICATE` | base64-encoded `.p12` signing cert |
| `APPLE_CERTIFICATE_PASSWORD` | password for the `.p12` |
| `APPLE_SIGNING_IDENTITY` | `Developer ID Application: Name (TEAM)` |
| `APPLE_ID` | Apple ID email for notarization |
| `APPLE_ID_PASSWORD` | app-specific password |
| `APPLE_TEAM_ID` | 10-char team ID |
| `TAURI_PRIVATE_KEY` | updater signing private key (minisign) |
| `TAURI_KEY_PASSWORD` | passphrase for the updater key |

## Updater public key

The public half of `TAURI_PRIVATE_KEY` lives in [`src-tauri/tauri.conf.json`](../src-tauri/tauri.conf.json) → `plugins.updater.pubkey`. If you rotate the signing key, **the new public key must be embedded BEFORE releasing** — otherwise existing installs won't trust the update.

## Auto-update endpoint

```
https://github.com/phuc-nt/my-media-kit/releases/latest/download/latest.json
```

Generated by the release workflow. Points at the most recent `Latest` release's artifacts + signatures.

## User-docs site

`user-docs/` → https://phuc-nt.github.io/my-media-kit/ via [`.github/workflows/pages.yml`](../.github/workflows/pages.yml). Pushes to `user-docs/**` on `main` auto-deploy. Pages source must be set to **GitHub Actions** (Settings → Pages → Source).

## Sanity checklist before tagging

- [ ] Version bumped in all three files
- [ ] `cargo check` + `cargo test` pass locally
- [ ] `npm run dev` launches and golden-path (transcribe + translate + summary) works
- [ ] User-facing changes reflected in `user-docs/README.md` if relevant
- [ ] Release notes drafted (paste into `gh release edit --notes` after CI)
